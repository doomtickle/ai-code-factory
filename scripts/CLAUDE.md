# scripts/: Dashboard Security Rules

Read before changing `scripts/dashboard*.py`, `patchview.py` or `dashboard-ui/`. Match these forms in `approvals.py`, `docs.py` and `factory chat` (`coordinator_attached`). History: docs/decisions/dashboard.md.

## Server and main page
- Bind 127.0.0.1 only. Require the per-run token on every request (swapped for an HttpOnly, SameSite=Strict cookie). Refuse any `Host` that isn't itself.
- Main port is GET-only: serve an allowlist of its own files, CSP with no inline script or style (`img-src 'self' data:` at most). `/docs/` is rendered once at start-up: no git, no `file://` links.
- Run no git of your own. Browser opener: fixed argv, no shell (never `explorer.exe`, `cmd.exe`, `powershell -Command`).
- Agent-written text reaches a page only as JSON drawn with `textContent` (SVG labels too), never HTML. Nothing from it becomes an attribute, URL, class name or title: a class is a key of a fixed table, a colour a validated `#rrggbb` via `style.setProperty`.
- Cookies ignore ports, so the cookie alone never authorizes an action. The main page only displays: no acting endpoint, no key; display-only features add none.
- Actions live on a second 127.0.0.1 port (own origin) the main page frames: Terminal 0 and the control unit. Main CSP adds only `frame-src` for it; iframes are `sandbox="allow-scripts allow-same-origin"`.

## Terminal 0
- Run exactly one of two fixed argv in a PTY, no shell, no shell fallback: `sbx run --name <NAME>` or `sbx run --name <NAME> -- --continue`, NAME `[a-z0-9][a-z0-9-]*`; only `coordinator_argv(name, resume)` builds it, no page text reaches it.
- Start only on an explicit page message (`resume` only JSON `true`/`false`, else drop); attaching a WebSocket starts nothing. Only when `sbx ls -q` lists the sandbox, `ps -axo pid=,ppid=,args=` shows no other `sbx run` naming it (any form), and shutdown hasn't begun. `factory chat` refuses likewise; `runs_sandbox` must match.
- Serve the terminal page only with `Sec-Fetch-Dest: iframe` and `Sec-Fetch-Site` `same-site`/`same-origin`, framed only by the main port. Accept its WebSocket only with that port's `Host`, `Origin` exactly `http://127.0.0.1:<termport>` or `http://localhost:<termport>`, the main cookie, and the per-run key in `Sec-WebSocket-Protocol`; write that key only into the terminal page.
- COPY: nothing the terminal prints reaches the clipboard by itself. No xterm.js clipboard addon; `term.js`'s OSC 52 handler is write-only: refuse queries and empty payloads, at most 64 KiB, drop control characters and any OSC 52 parsed in replay. A valid one only raises a prompt (preview by `textContent`, invisible/bidi characters made visible); only a click on COPY writes, dark for `HOLD_MS` (2.5 s) after each new text. Never read the clipboard. Only the terminal iframe gets `allow="clipboard-write"` (never `clipboard-read`; the Thoughtfield's adds only `microphone`); the control unit's frame gets none. Any other copy of agent text follows this rule.
- TALKING lives in `/term/field` only. Audio goes only to `POST /listen` on 127.0.0.1 with `credentials: "omit"`. Words leave only through `term.js` `typed()` (control characters removed): it never powers anything on; voice approves nothing and no agent reaches the voice service. `termFrame.focus()` only from a user action.

## Control unit
- `/cu`, `/cu/field`: own per-run key, never the terminal's. Serve only to a same-site iframe load, CSP with no inline script or style, `connect-src` only its own origin, framed only by the main port. Its script refuses to run top-level and removes the key from the DOM.
- Every action is `POST /cu/api/<name>` with a JSON body, read only when `Host` and `Origin` name the second origin exactly, `Sec-Fetch-Site` (if sent) is `same-origin`, exactly one dashboard cookie matches, the key is in `X-Factory-Control` (constant-time compare), `Content-Type` is JSON, and the body is at most 8 KiB (128 KiB for `config-prepare`), checked on `Content-Length` first. Refuse other methods (`OPTIONS` too); no CORS headers.
- `postMessage` is fixed words, checked on both ends, to the exact origin, accepted only from the expected window and `e.origin`: frame to main `cu:expand|collapse|reload|settings`; main to frame `{type:"cu:open",screen:"settings"}` and `{type:"cu:select",id}` (id fullmatches `[A-Za-z0-9_-]{1,64}`); terminal frame to main `t0:enter|out|still`; main to terminal `tm:hush|open|cancel`. A new signal is a fixed word from a fixed set, never words an agent or person wrote. Every word is a display hint that never presses a key, sends a request or acts. `cu:open`/`cu:select` act only on the deck (never over an open APPROVE question or a decision in flight) and restart the hold.
- APPROVE/DECLINE only through `approvals.write_decision`: exact card id, fingerprint `sha256(id NUL nonce)[:16]` matching, never an expired card, a decline needs a reason, one decision per card (hard-link, no replace). APPROVE and DECLINE stay dark for `HOLD_MS` after the card changes, in the INSPECT viewer too. APPROVE is one press; a truncated push asks first. The Thoughtfield's 2.5 s held press: `cu-field.js` sends no request and never sees the key, only clicks a key `cu.js` has enabled; the hold ends if the card changes; repo and branch stay in view.
- Host commands (RESTART, UPDATE, DIAG, APPLY: `<factory> restart`, `update --yes`, `doctor`, `config apply`): no single request starts one. `prepare` shows what it would do and returns a single-use token (120 s, bound to that action); only `run` with it starts the fixed argv (no shell, stdin `/dev/null`, own session, 0600 log), one at a time. APPLY refreshes only the bridge's snapshot, validated as `factory start` does.
- INSPECT acts on nothing: take `patch_sha256` only if it fullmatches `[0-9a-f]{64}`, open `approvals/patches/<sha>.patch` with every component `O_NOFOLLOW`, regular file, at most 2 MiB, serve only if its SHA-256 matches. `patchview.py` sanitises it, reading hunks by their header counts, never by what a line looks like (else a crafted patch shows what isn't approved); the main page never gets the patch or digest, and it never enters a card, webhook or audit record.
- SETTINGS is read-only: named policy keys only (never a credential; a URL's user, password, query, fragment cut), read with `dashboard_service.safe_read`. Anything moving the security boundary (broker policy and hosts, credentials, kits) is never edited.
- CONFIG WRITE (`scripts/dashboard_configwrite.py`) is the one config write: `FACTORY_CONFIG/roles/<role>.conf` and `FACTORY_CONFIG/projects/<project>[.<role>].md` only, via `config-read`, `config-prepare` (single-use 120 s token bound to the new bytes and file digest) and `config-run {"token"}` (under a lock; 409 if the digest moved). Name the target only from server-side facts, never a request path. An override takes `ROLE_OVERRIDE_KEYS` only (never `WORKSPACE`, `TEMPLATE`, `BROKER_TOOLS`), one line, no quote, backslash or control character, and must pass `roles.validate_role` first. Follow no symlink below `FACTORY_CONFIG` (`O_NOFOLLOW`, regular file, 0600 `O_EXCL` temp file, `os.replace`).

## Files the dashboard reads
- Open files under `FACTORY_STATE` or broker state as regular files with `O_NOFOLLOW`, size-capped, parsed as untrusted; match an id against its pattern (`JOB_ID`, card id, lane name) before joining it onto a path.
- `sbx` runs only as `sbx secret ls` and `sbx ls -q` (`Probe` refuses any other argv). What the page is given holds host-derived facts only: no credential, `[git].repos`, GitLab URL or notes contents.

## Invariants
- Anything new that lets a page act needs: one fixed argv with no shell, a key in a request header (not just the cookie) on a POST or WebSocket with its `Origin` checked, kept out of reach of the page that shows agent-written content, and a confirm step before any host command.
- Demo mode meets every rule above: no `FACTORY_STATE` or broker state, a fresh 0700 `mkdtemp` copy, and `DemoControls` write actions raise `Refused(403)` before any decision file, token, config write or host command; `argv()` raises. Never add a write outside that folder or a way to start a command.
