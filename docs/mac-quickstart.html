macOS · Apple silicon

AI Code Factory on your Mac

From a fresh Mac to a running Coordinator and role agents, each in its own sandboxed microVM. Setup takes about 20 minutes, most of it image builds.

macOS 14+ sbx 0.45.1 herdr 0.9.1 images v3 /usr/bin/python3 ≥ 3.9

Before you start

  • An Apple silicon Mac (M1 or later) on macOS 14 Sonoma or newer. Intel Macs aren't supported.
  • Docker Desktop, installed and running. It only builds the sandbox images.
  • A Docker account, for the one-time sbx login.
  • A Claude Pro or Max subscription. The agents sign in with it.
  • Homebrew, for jq. Everything else ships with macOS or the Xcode tools.
  • Access to the private repo doomtickle/ai-code-factory on GitHub.

Install

  1. Install the Xcode Command Line Tools and jq

    The Xcode tools provide git and the system Python that runs the dispatch bridge. Skip whatever you already have.

    xcode-select --install
brew install jq

    Then install Docker Desktop and start it.

  2. Give the Mac an SSH key for GitHub

    The repo is private, so cloning needs a key that GitHub knows. If ssh -T git@github.com already greets you by name, skip this step.

    ssh-keygen -t ed25519 -C "your-email@example.com"
pbcopy < ~/.ssh/id_ed25519.pub

    Paste the copied key at github.com → Settings → SSH and GPG keys → New SSH key, then check it:

    ssh -T git@github.com

  3. Clone the repo

    Pick a permanent spot. Setup links factory to this checkout, so if you move the folder later, run factory setup again.

    mkdir -p ~/code && cd ~/code
git clone git@github.com:doomtickle/ai-code-factory.git
cd ai-code-factory

  4. Check the machine

    doctor changes nothing. It lists each problem with the command that fixes it. Repeat until it reports No problems found.

    ./bin/factory doctor

  5. Run setup once

    It installs sbx and herdr at their pinned versions into ~/.local and checks their SHA-256 sums. It also builds the sandbox images, blocks outbound traffic by default, and links factory into ~/.local/bin. A browser window opens once for the Docker sign-in.

    ./bin/factory setup

    If setup says ~/.local/bin isn't on your PATH, add it to your shell profile:

    echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

    Homebrew sbx? If brew already installed a different sbx, run brew uninstall sbx, or keep ~/.local/bin ahead of /opt/homebrew/bin in PATH. The factory refuses to run on a version mismatch.

  6. Start the factory on a project

    Run it from the project folder: a git repository, or a folder of them. It opens Herdr with a Coordinator tab and one tab per role.

    cd ~/code/my-project
factory start
    coordinatorClaude on top, a host shell below
    developerLive transcripts: code, tests, docs on factory/* branches
    reviewerLive transcript: read-only review
    researcherLive transcript: the only role on the web

  7. Sign in to Claude, then start again

    The first time, type /login in the Coordinator pane and sign in with your Claude subscription. Then run factory start again from the host shell under it. sbx hands a sandbox the login only when it creates it, so the second start is what creates the role sandboxes.

    # in the Coordinator pane
/login
# then, in the host shell pane below it
factory start

  8. Give the Coordinator a job

    Describe the outcome you want. The Coordinator splits it into small pieces, picks a model and effort for each role, and gets the work reviewed. It asks before pushing or opening a PR.

    The developer works in its own clones of your project, from what is committed, so commit first. Its branches appear in your repository after each job; merge the one the Coordinator says is approved:

    git merge factory-developer/factory/rate-limit
    Research how to add rate limiting to the API, implement it with tests, and get it reviewed.

    Press Ctrl+B then Q to leave it running in the background, and factory start to come back. When the Coordinator suggests /compact or /clear between pieces of work, take it: that keeps every later turn cheap.

Everyday commands

CommandWhat it does
factory updatePull, rebuild and recreate whatever changed, then restart
factory statusProject, broker, bridge, login and sandbox status
factory logs developerFollow a role's transcripts, all its lanes (broker or dispatch for audit logs)
factory analyticsCost, tokens and model use per role (--html for a report)
factory stopStop agents, broker and bridge; state is kept
factory resetRemove agent sandboxes to switch projects; the login is kept

Worth doing next

Tell the roles your test command. Notes in ~/.config/ai-code-factory/projects/<project-folder>.md are added to every role's instructions on factory start. They live outside the project, so the roles can't change them.

mkdir -p ~/.config/ai-code-factory/projects
cat > ~/.config/ai-code-factory/projects/my-project.md <<'EOF'
- Tests: `factory-test -q -- npx vitest run` (`npm test` starts watch mode).
- Type check: `factory-test -q -- npx tsc --noEmit`.
EOF

Let agents push branches and open PRs. Add the repos to [git].repos in ~/.config/ai-code-factory/policy.toml and run factory setup. Then store a fine-grained GitHub token for the broker sandbox only. Agents can push only factory/* branches.

sbx secret set github --sandbox factory-broker

Updating the factory later takes one command. It pulls the latest code and rebuilds the images. Then it recreates only the sandboxes the changes affect, after listing them and what each one loses, and restarts the factory. Your Claude login is always kept.

factory update

GitHub token: if the broker gets recreated, sbx deletes the token you stored for it. Re-add it with sbx secret set github --sandbox factory-broker. factory update warns you before this happens, and factory start reminds you afterwards.

What was checked for macOS

  • ✓macOS on Apple silicon is a supported platform in factory doctor and the installer, which require macOS 14 or later.
  • ✓The pinned macOS downloads for sbx 0.45.1 and herdr 0.9.1 still exist and match their SHA-256 pins.
  • ✓Every script parses, and the role configs validate, under bash 3.2.57, the version macOS ships.
  • ✓The dispatch bridge and analytics test suites pass on Python 3.9, matching the macOS system Python.
  • ✓The scripts handle macOS differences: Keychain via security, shasum instead of sha256sum, and BSD-safe sed -i.bak.
  • !Not yet run end to end on a real Mac. Your first factory setup is the live test, and factory doctor names anything missing.
